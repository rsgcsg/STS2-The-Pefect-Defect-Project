## Release and recovery records

This file records the pre-release baseline; it does not claim that a future merge source was
already deployed. Final release notes and `combination.json` bind the actual main source,
Platform pin, lock, assets and OCI digest after current checks. The final release receipt is
attached to its exact main commit in `refs/notes/b-workflow-release` and linked by release notes.
Fetch that notes ref explicitly when auditing a checkout; absence is missing evidence.
Post-merge CI is source/test only. Changed STPD HEAD receives a fresh image/service/backup
qualification; unchanged native bytes retain their original build/load/Human identity.

Rollback selects matching predecessor image/config and a compatible verified closed DB
snapshot. The pre-release3555f09 rollback pairs the post-Human974c770/schema3 backup with
its matching974c770 image; the older schema2 migration snapshot does not contain the new
approved identity. Whole-host recovery also requires protected external configuration and
credentials; an SQLite restore alone does not prove it.

## Boundaries and maintenance

Existing-device email/approval and retained local/cloud parity are bounded Human evidence.
Live logout/reconnect was intentionally not executed; automatic regressions passed. New
accounts/devices/roles need their own canary. Account pairing is not campaign upload consent.
A collector must use the exact combination, a dedicated consented recording root and its
own Close-to-receipt check. Failed evidence stays failed even when transferred successfully.

There is no exhaustive native-content, new Full-Run runtime, research admission, training,
model quality, free-GPU availability, high availability, external outage notification or
whole-host disaster recovery claim. The initial release retains explicit developer toolchain
prerequisites and manual workbench reopening after reboot; it is not a player installer.

Owners monitor receipt completion, true failures, queue age, health, disk, budget and backup
freshness through the existing console/CLI. On failure preserve exact hashes/versions and
private evidence, isolate the affected scope, repair the first incorrect owning fact, regress,
release a new combination and canary the affected path. Do not erase errors or rewrite old
bundles to turn a failure green. See the owning collection guide and STPD Hub runbook.
