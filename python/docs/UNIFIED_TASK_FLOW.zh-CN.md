# SpireAgent 统一任务流程

状态：**本轮候选，正在集成和验证；尚未部署、完成新的真人验收或正式发布。**
下文说明候选界面的实际流程，不把源码实现当成线上能力。使用正式发布时，以该发布的安装说明和已验收范围为准。

这是成员的使用入口；安装细节见 [developer kit 安装](DEVELOPER_KIT_INSTALL.md)，工程与运维交接见[完整成员指南](../../docs/NEW_MEMBER_HANDOFF.zh-CN.md)。本页不建立第二套权限、队列、发布或研究规范。

## 1. 一套系统，三个地方各做一件事

| 入口 | 主要做什么 | 日常入口 |
|---|---|---|
| 游戏内 Mod | 亲自玩并录制，或让已准备好的模型测试；随时收回控制 | 真人采集、模型实战 |
| 本机工作台 | 连接这台电脑、准备录制、处理上传、下载与准备模型、看本机结果 | 真人采集、模型实战；数据和项目视图共用云端授权 |
| 云端 Hub | 看项目共享数据、建立数据集、查看训练模型和评估、管理成员 | 数据、数据集、训练与模型、评估结果 |

顶栏 **账号与电脑** 管登录与设备；**设置与诊断** 放版本、准备细节和维护信息。管理员另外看到 **成员管理**。云端不能替你操作本机游戏、选择本机目录或查看尚未上传的文件。

真人采集和模型实战是两个主要任务，使用同一个 Mod 和本机工作台。模型测试生成独立 Agent 记录，不能混入真人采集。角色、胜负、完整局或版本的研究要求在数据集选择时表达；日常不用发布或参加采集活动。

## 2. 谁需要什么权限

普通成员可以采集、查看获授权数据、建立和下载数据集、查看训练与模型、下载已发布模型并在兼容电脑上测试。管理员还负责邀请、停用成员、设备额度和项目设置。成员与管理员仍是两种角色，不增加采集员、研究员等等级。

GitHub 协作、Hub 成员和生产运维分别授权。会写代码不等于有 SSH 权限；能看训练页面不等于可以启动收费 GPU。首次接手工程按[成员指南](../../docs/NEW_MEMBER_HANDOFF.zh-CN.md)准备环境，研究任务按自己的数据契约和预算进行。

管理员通常只需：

1. 在 Hub 添加对方邮箱，允许登记电脑并设实际额度；已有成员不重复添加。
2. 发正式发布入口和本页。需要贡献代码时，另外邀请其 GitHub 账号。
3. 统一采集说明已存在时继续复用；需要修改时，到云端 **设置与诊断 → 采集说明设置**，填写用途和共享说明。普通软件更新不重新办理授权。

设备绑定由本人核对配对码，不需要管理员逐次批准上传。生产维护另外交接个人访问权限和恢复资料，不复制其他人的私钥或整套环境文件。

## 3. 全新成员、全新电脑

**首次安装与日常使用分开。** 下载一个模型或打开网页不能替代 Mod 安装、固定工具登记和原生加载检查。

1. 按正式发布的 [kit 安装指南](DEVELOPER_KIT_INSTALL.md)，准备固定运行目录、依赖、Mod 和工具。安装或替换 Mod 时必须完全退出游戏；开发目录继续用于分支和 PR。
2. 打开本机工作台，在 **账号与电脑** 点 **登录并绑定这台电脑**。用受邀请的邮箱收验证码，核对电脑名称与配对码并确认。无需新设项目密码。
3. 打开 **真人采集**，阅读简短说明后点一次 **同意并开启采集**。说明包含采集内容、项目存储以及哪些成员可访问；不再勾选三个框。
4. 工作台完成可自动做的准备。若提示填写游戏目录、退出游戏、重新打开游戏或启用 Mod，就完成该项，再点 **准备 / 继续检查**。页面显示真实下一步，不把等待当准备成功。
5. 准备好后在游戏内开始真人录制，做一段实际操作并点 **结束录制（Close）**。本机封包上传，在 **数据**中核对同一记录的云端回执。

只想查看共享数据或研究结果的人，可以直接登录云端，不需要先注册一台采集电脑。首次安装仍需要当前发布支持的系统和依赖，不宣称所有平台都已完成真人验收或安装器完全免配置。

## 4. 平时采集只做什么

打开原来的工作台和游戏，在游戏内开始录制，完成后结束录制。本机后台负责封包与上传，**真人采集**显示准备情况，**数据**显示记录和回执。

同一个账号、电脑配置、用途和共享范围保持不变时，不重新绑定、不重复同意，也不选择活动。旧授权、旧工具和队列保留原身份；发布新的默认说明不会改写旧录制。

一次 Close 结束的是一份录制，不一定是一局游戏。一份录制可以含多局或片段；没有可靠终点时就是不完整或未知，游戏失败也不等于全部决策不可用。

| 界面事实 | 该怎么理解 |
|---|---|
| 准备好 | 本次准备检查满足，可以开始新的真人录制 |
| 待封包 / 待上传 / 上传中 | 原始文件和队列仍在本机；云端还不能据此说已验收 |
| 云端已验收 | 对应包的接收/验证已产生回执；训练资格和样本选择另看质量报告 |
| 失败或未知 | 看原因与对应 ID；保留原数据，不把失败改成成功 |

版本、路径、详细检查放在折叠详情；需要处理问题时再展开。成功数量、真实失败、未解决和诊断信息继续分开，不因界面简化而合成一个虚假的成功率。

## 5. 暂停、离线、换账号与恢复

| 情况 | 系统怎么处理 | 成员怎么做 |
|---|---|---|
| 只关闭网页 | 工作台后台仍可能运行并上传 | 暂停上传要点 **暂停自动上传**；停止整个后台用既有停止入口 |
| 退出网页账号或会话过期 | 个人项目浏览会话与设备凭据分开；登出不撤销设备上传 | 需要看项目数据时重新登录，不重新建立采集配置 |
| 暂停自动上传 | 持久保存暂停偏好；重新打开工作台仍暂停 | 需要时点 **恢复自动上传**，重新核对权限与准备状态 |
| 暂停时已有上传在处理 | 已提交的字节可能已到云端；停止失败不算确认暂停 | 等真实进程状态与最终回执；不要删除 pending 行 |
| 普通网络中断 | 本地录制与队列保留，已设计的传输恢复继续使用原任务身份 | 联网后看原任务；不反复新建相同上传 |
| 成员或设备授权被撤销 | Hub 拒绝后续受限请求；本机不能自行恢复权限 | 先处理授权；认证阻塞记录通过 **恢复已修正授权的上传**核对恢复 |
| 准备步骤中断 | 已完成的 owner 状态保留 | 重新打开后点 **准备 / 继续检查**，从事实读取下一步 |
| 同电脑换另一个人 | 登录不转移原设备、录制或队列归属 | 使用另一份私有配置和清楚的设备名，最好用独立 OS 用户 |
| 要彻底撤销这台电脑的后续上传权限 | 云端 **账号与电脑**可以撤销所管理设备 | 历史数据不自动删除，已经下载的副本也不会被远程收回 |

设备是一次工作台配置登记，不是硬件指纹。不要为解决普通错误重复注册电脑、拷贝别人的凭据或覆盖旧 outbox。离线本机仍可请求暂停；恢复上传需要验证当前账号和原设备授权。

## 6. 从数据到数据集，再拿去训练

**数据**回答“收到了什么”：录制、云端回执、质量、局与片段、统计和下载。上传次数、去重内容、有效决策数、已观察局数分别显示，不能互相冒充。统计有覆盖范围或缺失摘要时保留提示。

**数据集**回答“这次研究选哪些样本”：

1. 选择已收到的录制。默认允许不完整局、失败局中的有效决策以及不同游戏版本；可按需要展开角色、版本、完整局、已确认胜利等筛选。
2. 点 **预览选定记录**。后台显示读取、校验、筛选等阶段及耗时；可以离开页面，回来查看同一个任务。
3. 检查保留、排除、重复以及版本/角色等分布，点 **按此预览生成固定数据集**。新上传不会偷偷改变这个固定版本。
4. 从数据集进入下载，等待固定文件清单，核对字节与校验结果，再交给支持该契约的研究入口。

已建的数据集也能合并：勾选若干项，点 **合并选中数据集 · 先预览**，随后生成新版本。只取父数据集已经选中的行，按精确决策身份去重并检查冲突；不会重新从原录制扩大选样。原版本和来源保留，两个片段也不会凭拼接变成完整局。

新合并版本重新按真实局分组划分，不能把同一局或重复内容拆到 train/dev/test 两边。已经用于训练或调参的数据，即使重分组也不会成为新的无偏测试集。序列学习遇到缺口必须断开或 mask；单步成功样本不保证连续记忆训练可用。

任务进度是可恢复查看的状态，不是任意阶段的继续计算检查点。worker 中断会留下失败；修复原因后显式重新尝试，原失败保留。验证缓存可以节省重复投影，但仍查权限与原始内容；本轮只有有边界的本地测量，没有生产速度或百局吞吐承诺。

数据集建立、合并成功不等于现有训练器都能读取。决策数据集/合并契约与旧严格 Full-Run 训练入口不同，须先核对 loader 与研究协议。**训练与模型**展示实际已登记任务和产物，不自动启动训练；当前没有新预算时不启动 GPU 或收费任务。细节分别由[数据集 ADR](adr/0007-fixed-decision-datasets.md)、[合并 ADR](adr/0008-selected-decision-unions.md)和[训练指南](FULLRUN_TRAINING.md)负责。

## 7. 模型下载、实战、接管与分享

1. 在 **训练与模型**查看模型和适用说明，需要时下载固定产物。下载只保存并校验文件，不会让任意 checkpoint 自动获得执行资格。
2. 在本机 **模型实战**选择已支持模型，点 **准备并加载**。工具检查文件、适配器、固定 Runtime、硬件和表示契约；缺少什么就指出什么。当前 S1 仍需 CUDA；没有相应硬件或本地权重时停在明确的准备状态，不暗中下载大权重或启动云 GPU。
3. 加载完成仍是人工控制。本人在本机或游戏内点 **开始测试**，系统先让 Recorder 结束真人录制，确认同一游戏实例已准备好后才切换模型。Close 待完成、失败或响应未知时不接管。
4. 需要自己玩时点 **暂停并接管**；准备结束本次测试时点 **结束测试**。这些操作也在游戏内，日常不必反复切网页。只评分、单步和 Tick 留在高级控制。
5. 后台观察真实 Runtime 停止并校验封存证据，在 **评估结果**产生本机实战记录；无需靠打开页面触发生成。缺失、未封存或校验失败显示真实原因。
6. 希望项目成员查看时，在本机记录旁点 **分享本次实战记录**。按钮旁说明该次游戏状态、动作和模型身份会上传给获授权成员。真人采集授权不代替这次操作；本轮不自动分享所有实战记录。

**暂停并接管**不保证已提交动作可以撤回。系统会阻止旧的准备或模式响应在接管后继续发起迟到的 Auto/Tick，未知交付不自动重发。Runtime 或游戏连接未知时先核对状态；结束测试与关闭网页不是同一件事。恢复真人采集要开始新的录制，模型测试不会自动变成真人数据。

分享使用当前个人账号和其有效设备授权。Hub 再次校验原始 Agent 证据，生成独立实战产物；不进入真人上传表。原始证据总量当前上限 16 MiB，超限保留本机数据并明确报错，不截断成一个貌似完整的报告。分享响应未知时不自动重发；核对后显式重试仍按不可变内容去重。

当前报告的“已校验”指**成员提交的 Agent 证据完整性与内部一致性**，不是对不可信客户端游戏过程的独立证明。游戏胜负、完整局和完整自主控制覆盖尚未测量，因此不能把结束测试当胜利、把技术运行成功当游戏成功，也不能给出已验证的模型胜率。离线模仿人类的结果与游戏实战分开显示。准确接口与限制见[模型任务和分享](LOCAL_MODEL_TASK_FLOW.md)。

## 8. 游戏或软件更新时

默认记录实际版本，继续使用明确的固定发布。新 main 提交、Hub 更新或另一成员升级，不自动要求所有电脑和模型同步升级。后台可以核对来源与兼容性，但不能替未知游戏版本制造原生支持证明。

- 游戏或 Mod 变化影响原生加载/执行时，按原生适配与安装检查处理；只限制实际受影响能力，已有原始数据保留。
- Hub 接收按权限、完整性和受支持格式判断，不按“是否最新 SHA”判断；数据集保留版本分布。
- 模型按其文件、适配器、输入与动作契约判断能否运行；游戏版本可混入数据集不等于一定适合混合训练。
- 升级沿用既有 tool/队列迁移入口，pending 数据不能通过删队列或改身份绕过。旧 API 和旧队列不会因新界面改名而改写。

精确规则只由[版本与兼容性](../../docs/VERSIONING.md)、[安装指南](DEVELOPER_KIT_INSTALL.md)和 owning 契约维护。功能正常且没有安全、正确性或兼容性问题时，成员不需要因文档修改重装。

## 9. 出错后，最短的闭环

先在当前页面读状态与下一步，再到 **设置与诊断**看详情。报告留下时间、系统/发布、当前任务阶段、recording/upload/dataset/evaluation/job ID、期望和实际、脱敏错误。不要贴验证码、Cookie、Token、完整环境文件或原始私人录制。

后台任务失败保留原记录；工程师定位最先出错的 owner，用新的 branch/PR 修复并加有效回归。普通任务经检查合 develop；需要正式交付时才经 release PR 进 main，发布受影响产物，云端和本机按具体部署验收更新。两个长期分支不妨碍使用临时开发分支，也不能成为删除别人未合并工作的理由。

操作员负责界面使用和真实游戏，管理员负责成员与共享设置，工程师负责通过 PR 修复，运维负责已授权的生产部署与恢复。一个人可以承担多项工作，权限和证据仍分别核对。完整规范继续由[开发流程](../../docs/DEVELOPMENT_WORKFLOW.md)、[测试](../../docs/TESTING.md)、[Hub RUNBOOK](../deploy/hub/RUNBOOK.md)维护。
